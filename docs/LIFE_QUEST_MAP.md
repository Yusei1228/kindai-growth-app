# LIFE QUEST MAP（大学生活すごろく）設計メモ

現実の大学生活そのものを人生ゲーム化するキー機能。MVP を「ローカルファースト（Supabase 無改変で動作）＋サーバー権威化しやすいデータ構造」で実装済み。

## 0. 「人生ゲーム」がなぜハマるのか（分析）と、アプリへの落とし込み

任天堂スイッチ等の「人生ゲーム」を分析し、中毒性の源泉を抽出して本アプリに翻訳した。

| 人生ゲームのハマる要素 | 仕組み（心理） | 本アプリへの落とし込み |
|---|---|---|
| **ルーレットの偶然性** | 「いくつ進むか」が運＝変動報酬（次が読めない期待感） | 🎡 ルーレット（1-6）を回す「マイターン」。回転演出＋針。 |
| **先が見える道＋未知のマス** | 盤面の先が見える→行きたくなる。止まるまで内容不明のドキドキ | 縦スクロールの長い道（約45マス）。先のマスは薄く見える。止まって初めて“今日の占い/イベント”が起きる。 |
| **人生の物語（就職・結婚・家・株）** | 自分のコマに出来事が積もり「自分の物語」になる（自己投影） | 「大学生活の物語」：占い（今日の過ごし方）・イベント・中間ゴール。達成履歴＝MY STORY（アルバムの芽）。 |
| **一発逆転・波乱** | 大きな＋/−で順位が動き最後まで分からない | 特別イベントマス（大量SP／もう1回／ハプニング）。 |
| **分岐ルート** | 進路選択で毎回違う人生＝リプレイ性 | テーマ10種＋各ルート内の分岐（選択で以降のマス・ゴール文言が変化）。 |
| **マイルストーンのご褒美** | 給料日等の小さな payoff の連続 | 中間ゴール（1/3・2/3地点）で演出＋大報酬。 |
| **収集・成長の可視化** | お金・家族・資産が増える手応え | SP/EXP/レベル/ステータス/コインの可視化（既存資産に接続）。 |
| **社会的比較** | 他人と比べる競争 | 既存ランキングに接続（サブ機能として存続）。 |
| **1ターンの低摩擦** | 回すだけ→「あと1回だけ」 | 1タップで回す。ただし**1日のターン数を制限**し“毎日ちょっと”の習慣に。 |

**最重要の翻訳**：人生ゲームは「運で進む」が、本アプリは**止まったマスの“現実の行動(課題)”をやって初めて前進**する（占い/イベント/中間ゴールは自動解決でテンポを作る）。＝ゲームの楽しさ×現実の行動変容。

**規模とペース**：盤面 約40〜50マス、ルーレット1-6、**1日3ターン**（`LIFE_DAILY_ROLLS`・ボーナスマスは消費しない）。→ 約2週間でゴールに到達する“旅”になる。数値は調整可能。分岐と中間ゴールは**強制停止**（飛び越えない）。

## 1. 体験（コアループ）

```
テーマ選択（何を充実させたい？）
   ↓
🎲 マイターン：サイコロを振る
   ↓
キャラ（アバター）がマップ上を出目分だけ1マスずつ進む
   ↓
止まったマス＝現実の小さな行動（今日の行動）／イベント／分岐
   ↓
現実で行動 → 達成 → SP/EXP/ステータス付与
   ↓
次のターンへ（＝また現実で動きたくなる）
   ↓
ゴール（現実の願いの達成）＝ QUEST COMPLETE
```

- 「サイコロを振るだけで進む」ではなく、**止まったマスの行動を現実でやる**ことが前進の核。イベント/ボーナス/ひとやすみのフィラーマスだけは自動解決してテンポを作る。
- 分岐マスの選択（例：国内旅行/海外旅行）は `variant` として保存し、以降のマス文言・ゴール文言（`{v}`）を書き換える＝「選択でその後が変わる」。

## 3. 配置（指示4・5の遵守）

- **下部ナビ**：`ランキング` を撤去し `すごろく（LIFE MAP）` を設置。
- **ランキングは削除していない**：ホームの「大学」丸ボタン → `ranking` 画面へ遷移する導線を維持（`←` で戻れる）。ランキングの画面・データ・集計ロジックは無変更。競争したい学生向けのサブ機能として存続。

## 4. データモデル

- `LifeNode`：`{ id, kind: quest|branch|goal|event|bonus|rest, title, hint?, emoji, category, sp, exp, stat, choices? }`
  - `category` は既存 `Category`（勉強/運動/生活習慣/振り返り）→ `CATEGORY_TO_STAT` で 知力/体力/活力/魅力 に接続。
- `LifeRoute`：`{ id, theme, emoji, color, tagline, nodes[] }`（先頭=最初のマス、末尾=goal）。
- 盤面 `getBoard(routeId)`：`nodes` の行動/分岐マスの後ろへイベント/ボーナス/休憩フィラーを**決定的に**挿入（id固定）。位置がセッションを跨いで安定。
- 進捗 `LifeRouteProgress`：`{ pos, awaiting, variant, done, lastRoll? }`（pos=-1 が START）。ルートごとに保持＝将来の複数同時進行に拡張しやすい。
- 履歴 `LifeHistoryEntry[]`：達成マスを保存（「大学生活アルバム / MY UNIVERSITY STORY」の元データ）。

## 5. 既存資産の流用

- **SP/EXP/レベル/ステータス/コイン**：`rollLifeDice`/`resolveLifeSquare` 内で既存と同じ計算（`expForLevel` によるレベルアップ、`Math.min(100, …)`）を適用。
- **アバター**：`components/Avatar` の `MiniAvatar` をコマとして再利用。
- **ランキング反映**：付与後に既存 `syncStats(total_score=sp …)` を呼ぶため、Supabase 接続時は**追加テーブル無しで既存ランキングに自然に載る**。
- **デザインシステム**：`styles.css` のトークン（--ink/--line/--shadow-*/--radius）と `.overlay/.levelup/.btn-primary` を流用。ルート色は `--rc` を各要素にインラインで供給。

## 6. 新規に必要なもの（MVPで実装済み）

- ルート定義・盤面生成・サイコロ進行ロジック・LIFE MAP 画面・すごろく用スタイル・下部ナビ差し替え。

## 7. セキュリティ / DB（現状と将来）

- **現状（MVP）**：LIFE MAP 進捗は `AppState.lifeMap`（localStorage）に保持。SP/EXP はこれまで同様 `auth.uid()` 基準の `syncStats`（既存の profiles 更新経路）で反映。**本番 Supabase は無改変**。
- **将来のサーバー権威化（推奨・未実装＝要承認）**：
  - テーブル：`life_routes`(公開読・マスタ), `life_progress`(user_id=auth.uid(), route_id, pos, variant, done, updated_at), `life_history`(user_id, route_id, node_id, kind, sp, exp, at)。すべて本人限定 RLS（報酬機能と同型）。
  - RPC(SECURITY DEFINER・PUBLIC/anon から EXECUTE 剥奪)：
    - `life_roll(route_id)`：サーバーが乱数で出目を決定し pos を進め、フィラーは即時解決して SP/EXP を付与（＝出目とスコアの改ざん不能）。
    - `life_resolve(route_id, choice?)`：止まったマスの行動達成/分岐/ゴールを確定し SP/EXP/ステータスを付与。
  - クライアントは pos/variant/done/スコアを**直接更新しない**（報酬機能と同じ「サーバー権威」方針）。
  - データ構造は上記へ 1:1 で移行できるよう設計済み（`LifeRouteProgress`/`LifeHistoryEntry` がそのまま行になる）。

## 8. スケール（50 → 500 → 6,000 人）

- 盤面・ルートは**クライアント同梱の純データ**（読み取りのみ）。ユーザーあたりの書き込みは進捗1行＋履歴の追記のみで軽量。
- Supabase 権威化後も、1アクション=RPC1回・進捗upsert1回で、6,000人規模でも Pro プラン相当で十分（既存の報酬/ランキングと同オーダー）。
- **AI をマスを開くたびに呼ぶ設計は不採用**（高コスト）。

## 9. 将来 AI 適応（拡張ポイント）

- 方針：**テンプレートベース ＋ 必要時のみ AI 調整**。
  - 例：ある行動マスで3日以上 `awaiting` が続く → 「もっと小さな行動に変えませんか？」と提案し、途中に軽いマスを1つ挿入。順調なら少し難しいマスを提案。
  - 実装フック：`LifeNode` は純データなので、AI 生成マスを「盤面へ差し込む」だけで拡張可能。呼び出しは**イベント駆動（停滞検知時など）でバッチ的に**行い、常時 API 呼び出しはしない。

## 10. 想定リスクと対応

- **クライアント改ざん**（pos/スコア）：MVP はローカル値のため厳密な不正対策は未。→ §7 のサーバー権威化で解消（承認後）。ランキングに載る SP は最終的に RPC 経由へ。
- **マス文言のロジック順が崩れる**（サイコロで行動マスを飛ばす）：人生ゲームの仕様として容認。各マスは単体で成立する行動に設計。ゴール到達はサイコロで必ず可能（オーバーフローはゴールにクランプ）。
- **背景が夜間で低コントラスト**：ピッカー見出しは半透明スクリム、盤面は白カードで担保。
- **多言語/長文マス**：カードは折返し前提。将来 AI 生成文言は文字数ガードを推奨。
