## 1. デイリーミッションの目的

- ユーザーが毎日「小さな努力」を継続できるよう、**その日に取り組む固定候補ミッション**を提示する。
- 達成でSP（ランキング）/EXP（レベル）/ステータスが伸び、努力が数値・見た目に即時反映される「体感」を作る。
- 3件すべて達成で**完全達成ボーナス**（EXP+40）を付与し、毎日やり切る動機を作る（`GAME_LOGIC.md §4`）。

---

## 2. 1日3件の設計

- 1日に **デイリーミッションを3件** 提示する（`slot_no` = 1 / 2 / 3）。
- 対応DB（`DB_SCHEMA_V2` `user_missions`）:
  - `mission_source = 'daily'`
  - `app_date` = その日の論理日付（§3 朝5時切替）
  - `slot_no ∈ {1, 2, 3}`
  - daily用UNIQUE `(user_id, app_date, slot_no)` で「1日3枠・重複配布なし」を保証。
- **`要確認`（配布ロジック）**: 3件を **どう選ぶか**（D001〜D054からのランダム/カテゴリバランス/ユーザー目標連動）はNotion未記載。MVPは「固定 or 単純ランダム3件」で暫定、選定アルゴリズムは `TODO`。
- **`要確認`**: 3件のカテゴリ配分ルール（知力/体力/活力/魅力を必ず混ぜるか等）未定義。

---

## 3. 朝5時切替のルール

- **1日の区切りは午前5時**。0:00〜4:59 の実行は**前日扱い**（`app_date` は前日）。
- `app_date` はこの朝5時基準の「アプリ論理日付」であり、実時刻の暦日とは別（`DB_SCHEMA_V2` `user_missions.app_date` と整合）。
- 判定は**サーバー側**で行う（クライアント時計を信用しない／`GAME_LOGIC.md §9`）。
- **`要確認`**: タイムゾーンは JST 固定か（`TODO`: 明記）。全達成ボーナス・ストリーク継続判定もこの朝5時境界に従う想定（`GAME_LOGIC.md §4/§6`）。

## 4. daily と self の違い

| 項目 | デイリー（daily） | セルフ（self） |
|---|---|---|
| 配布 | 運営提示・1日3件（slot 1〜3） | ユーザーが任意に追加 |
| SP/EXP | **ミッション固定値**（§6 D001〜表） | **時間ベース**（`GAME_LOGIC.md §1-2`） |
| ステータス | 難易度別の固定上昇値×成長倍率 | 時間別基礎値×セルフ係数×成長倍率（`STATUS_GROWTH_RULES.md`） |
| 回数 | 1日3枠 | 制限は `要確認`（日記のみ1日2回上限） |
| DB | `user_missions`(`mission_source='daily'`, `slot_no`) | `user_missions`(`mission_source='self'`, `slot_no=null`) |
| 完全達成ボーナス | あり（3件全達成でEXP+40） | なし |

## 7. 各ミッションの報酬係数・難易度・所要時間の考え方

- **SP/EXP**: 上表の固定値（デイリーは時間で変動しない）。
- **難易度**: 低 / 中 / 高。ステータス上昇の基礎値と連動（`STATUS_GROWTH_RULES.md`）:
  - 通常ステータス（知力/筋力/活力）: 低 +0.7(補助+0.2) / 中 +1.0(補助+0.3) / 高 +1.3(補助+0.4)
  - 社交性（魅力）: 低 +1.0 / 中 +1.4 / 高 +1.8（他より高め）
- **管理方法（記録手段）**: タイマー / チェック＋レビュー / レビュー / タイマー＋レビュー。
  - タイマー系 → `mission_logs.duration_minutes` を記録。
  - レビュー系 → `mission_logs.review_text`（日記は `text_content`／文字数）。
  - チェック系 → 実行チェックのみ（`要確認`: 証跡不要かどうか）。

## 8. 完全達成ボーナス

- **デイリー3件を全達成 → ボーナスEXP +40**（`GAME_LOGIC.md §4`）。
- 判定: `user_missions` で当日（`app_date`）の `slot_no` 1〜3 が全て `completed`。
- `要確認`: SP/コイン/ステータスのボーナス有無は未記載（EXP+40のみ確定）。付与は1日1回想定（`TODO`: 明記）。

## 9. DB保存の前提（`user_missions` / `mission_logs`）

### `user_missions` に保存する前提
- デイリー配布・進捗をここで管理（`mission_source='daily'`, `app_date`, `slot_no`, `status`, `completed_counted`）。
- セルフミッションも同一テーブル（`mission_source='self'`, `slot_no=null`）。
- 全達成判定・報酬付与済み管理に `completed_counted` を使用。

### `mission_logs` に記録する前提
- 実行1回ごとの記録（`duration_minutes` / `review_text` / `text_content` / `evidence_image_url` / `status` / `is_suspicious`）。
- 同一ミッションの複数回記録を許容（UNIQUEを張らない）。報酬二重付与防止は `score_logs`（冪等キー）で担保（`DB_SCHEMA_V2 §3/§4`）。
- 報酬（SP/EXP/ステータス/コイン）の確定はサーバー計算 → `score_logs` へ明細、`season_user_scores`/`profiles`/`user_stats` へ反映（`GAME_LOGIC.md §9`）。
