## 3. ステータス上昇計算式

### 3-1. デイリーミッション
```
実際のステータス上昇値 = 基礎上昇値 × 成長倍率
```
- 基礎上昇値 = ミッション定義の主/補助ステータス値（難易度で決まる。§3-3）。
- 成長倍率 = 現在のステータス値による逓減（§5）。

### 3-2. セルフミッション
```
実際のステータス上昇値 = 基礎上昇値（時間ベース）× セルフステータス係数 × 成長倍率
```
- 基礎上昇値 = 所要時間に対応する値（§4 時間→基礎上昇値表）。
- セルフステータス係数 = 行動内容ごとの係数（§4 係数表）。
- 成長倍率 = §5。

> **注意（SP係数と別物）**: ここで使う「ステータス係数」は `GAME_LOGIC.md §1-2(b)` の「SP係数」とは**別テーブル・別値**。SP計算にはSP係数、ステータス計算にはステータス係数を用いる（`要確認`: 2種類の係数が併存する点を実装で取り違えないこと）。

## 4. セルフミッションの 時間・係数

### 時間 → 基礎上昇値
| 時間 | 基礎上昇値 |
|---|---|
| 3分 | +0.2 |
| 5分 | +0.3 |
| 10分 | +0.6 |
| 30分 | +1.3 |
| 60分 | +2.8 |
| 90分 | +3.6 |
| 120分 | +4.5 |
| 300分 | +5.4（121〜300分は延長・下記） |

> **【確定】121〜300分の延長（低い伸び率）**: SP同様、ステータスも300分まで少しだけ反映する。
> - **0〜120分**: 上表（3/5/10/30/60/90/120分の点）を使用。
> - **121〜300分**: 120分時点の基礎上昇値 **+4.5** を起点に、**1分あたり +0.005** で加算。
>   - 300分 → +4.5 + 0.005×(300−120) = **+5.4**。
> - **300分を超えた分はステータス報酬なし**（記録のみ）。これにより5時間の努力も少し反映されるが、急激には上がらない。

> **【確定】非標準時間の補間（線形補間）**: 表にない時間（例 15分・45分）は、**前後の表点の間を線形補間**で算出する。
> - 例: 15分 → 10分値(+0.6) と 30分値(+1.3) の間を線形補間 → +0.6 + (1.3−0.6)×(15−10)/(30−10) = **+0.775**。
> - 例: 45分 → 30分値(+1.3) と 60分値(+2.8) の間を線形補間 → +1.3 + (2.8−1.3)×(45−30)/(60−30) = **+2.05**。
> - 各区間（3–5 / 5–10 / 10–30 / 30–60 / 60–90 / 90–120分）の端点を結ぶ直線で内挿。121〜300分は上記の延長式（+0.005/分）を使う。
> - なお、SP/EXP/ステータスの報酬対象は**同一種別の当日累積時間**で計算し（差分付与・`GAME_LOGIC.md §1-2`）、**当日合計300分**で頭打ち（実行時間そのものは `mission_logs` に記録）。

|---|---|---|
| 勉強 | 知力 | 1.00 |
| 読書 | 知力 | 0.85 |
| 筋トレ | 筋力 | 1.15 |
| ランニング | 筋力 | 1.15 |
| ストレッチ | 筋力 | 0.80 |

- **勉強60分・現在の知力85（倍率0.6）**: `2.8 × 1.0 × 0.6 = +1.68`

## 5. 成長倍率（時間・難易度以外の主要補正）

現在のステータス値が高いほど上がりにくくする。

| 現在値 | 成長倍率 | イメージ |
|---|---|---|
| 20〜59 | 1.0倍 | 序盤は上がりやすい |
| 60〜79 | 0.8倍 | 少し上がりにくい |
| 80〜94 | 0.6倍 | 継続が必要 |
| 95〜100 | 0.4倍 | カンスト直前は重い |

- **【確定】成長倍率は、上昇する各ステータスごとに、そのステータスの現在値を見て個別に適用する。**
  - 例: 知力と活力が同時に上がる場合、**知力deltaには現在の知力に応じた倍率**、**活力deltaには現在の活力に応じた倍率**を使う（主/補助でまとめて同じ倍率にはしない）。
  - 主ステータス・補助ステータスそれぞれ、対象ステータスの現在値でテーブルを引く。

## 6. 時間・難易度・達成度による補正のまとめ

| 補正要素 | daily | self | 備考 |
|---|---|---|---|
| 時間 | ミッション文面に内包（固定） | **時間→基礎上昇値表**で反映 | selfは所要時間が主要因 |
| 難易度 | **難易度別 基礎上昇値**（§3-3） | （明示なし） | dailyの主要因 |
| 成長倍率 | 適用 | 適用 | 現在値による逓減（§5） |
| セルフ係数 | — | 適用 | 行動内容別 |
| 達成度 | **使わない（報酬に不反映）** | **使わない（報酬に不反映）** | 下記参照 |

> **【確定方針】達成度・レビューは報酬計算に使わない（MVP）**:
> - ステータス／SP／EXP／コインの計算に、達成度（★評価等）や自己評価は**一切反映しない**。
> - 理由: ①自己申告で不正しやすい ②SP/ランキング/店舗特典（実利益）に影響するため危険 ③MVPはシンプルな計算（時間・難易度・カテゴリのみ）にした方が安全。
> - **達成度・レビュー文は「振り返り・自己分析・将来のAIコーチ用データ」として記録**する（`mission_logs.review_text` / `text_content`。日記のみ文字数がSPに使用＝`GAME_LOGIC.md §1-3`）。
> - 旧プロトタイプの「達成度★でSP加点」は本仕様で**廃止**（`GAME_LOGIC.md §11`）。

## 7. 上限値の考え方（クランプ確定）

- **ステータス上限は表示上100（DB保存値 1000）／下限は表示上20（DB保存値 200）**。初期20（保存200）。
- **【確定】計算結果が100を超える場合は100でクランプ**する（サーバー計算側で実施）。
- **【確定】`score_logs` には理論値ではなく「実際に加算されたdelta」を記録**する。
  - 例: 現在 99.5、計算上 +1.0 の場合 → 実際は 100.0 までの **+0.5 だけ反映** → `score_logs` の delta は +0.5 相当（**×10保存で +5**）。`user_stats` は 995 → 1000。
- 成長倍率により高レンジは実質的に到達が重くなる（95〜100は0.4倍）。
- 時間ベースの基礎上昇値は**300分（+5.4）で頭打ち**（0〜120分は表、121〜300分は+0.005/分の延長。300分超は報酬なし・記録のみ。`GAME_LOGIC.md §1-2/§7`）。

## 9. DB保存の前提（`user_stats` / `score_logs`）

### `user_stats` に記録する前提
- 各ユーザーの **現在のステータス値**（`intelligence` / `strength` / `vitality` / `charm`）を保持。
- **【確定方針】ステータスは10倍した整数で保存する**（`user_stats.*` はint系のため）:
  - 表示 12.3 → DB保存値 **123** ／ 表示 45.0 → DB保存値 **450**。
  - 初期値20 → 保存 **200**、最大100 → 保存 **1000**、最低20 → 保存 **200**。
  - UIでは必要に応じて **÷10** して表示。
  - `TODO`（表示のみ）: MVPの表示を「小数1桁」か「整数」かは未確定（保存方式は×10で確定）。
- ミッション達成のたびにサーバー計算で更新（クライアント直接更新禁止・`GAME_LOGIC.md §10`）。

### `score_logs` に記録する前提
- 1回の報酬付与ごとに、ステータス増減を明細として記録（`intelligence_delta` / `strength_delta` / `vitality_delta` / `charm_delta`）。
- **【確定】×10整数化の端数処理**: ステータスdeltaは、**計算後に×10して四捨五入し、整数で `score_logs` に保存**する。
  - 例: +2.84 → 28.4 → **28** ／ +2.85 → 28.5 → **29**（四捨五入）。
  - `user_stats` には、この**整数delta（×10）を加算**する。
  - 100クランプ（§7）を適用した「実際に反映されたdelta」を記録する（理論値ではない）。
- 併せてSP/EXP/コイン（`season_point_amount` / `exp_amount` / `coin_amount`）も同レコードで記録し、監査・再計算の元にする（SPは`GAME_LOGIC §1`で5単位丸め済み整数）。
- 二重付与防止（冪等キー）と書き込みサーバー限定は `DB_SCHEMA_V2 §4` / `GAME_LOGIC.md §9-10` に従う。
