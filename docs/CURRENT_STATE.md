## 8. SP・EXP・ステータス計算の場所

すべて `src/store.tsx` の `completeMission()` に集約:

- 目標超過分（`minutes - targetMinutes`）に応じて SP / EXP ボーナス。
- 達成度★4以上で SP +5。
- EXP がレベル閾値に達したらレベルアップ（複数レベル繰り上げ対応）、レベルアップで +20 ポイント。
- レベル閾値: `expForLevel(level) = 80 + level * 60`（`data/types.ts`）。
- ステータスは `Math.min(100, …)` で上限100。

## 12. 技術的に危険そうな箇所

1. **localStorage のスキーマ無検証**: `loadState()` は `JSON.parse` のみで型・バージョン検証なし。`seed` の構造変更時に旧データで画面クラッシュの可能性。マイグレーション機構なし（キーは `v1` 固定）。
2. **連続日数（streak）がリセットされない**: 達成日があれば `+1` するのみで、日が空いても減算・リセットされない。実質「累計達成日と同じ単調増加」。
3. **デイリー報酬が"デイリー"でない**: `dailyRewardAvailable` は claim で `false` になるだけで、翌日 `true` に戻る処理がない（一度きり）。
4. **`challengeDaysLeft` が静的**: seed の `6` のまま減算されない。

---

## 13. 既存仕様と矛盾しそうな箇所

1. **自分の月間ランキングだけ計算基準が異なる**: 他ユーザーは個別 `monthlySP` で比較する一方、自分は `state.user.sp`（累計SP）を月間値に流用。週間=直近7日ログ集計／月間=累計、と基準が不統一で順位が実態とズレる。
2. **週間SP集計と seed 初期値の不整合**: `meWeeklySP()` は直近7日のログ合計だが、seed のログは1件のみ。一方プロフィールは Lv23・SP2,350・連続45日。→ 設計画像では上位なのに、ランキング上の自分は週間SPがほぼ0で最下位付近に表示される矛盾。
3. **学部のハードコード**: 自分の学部が `'経済学部'` 固定（`store.tsx`）。認証/プロフィール未実装ゆえだが、学部別フィルタの正確性に影響。
